Vitalia Health Insurance

HAR on-device + Detección de Caídas · Caso 06 · Equipo Íñigo + Jaime

Arquitectura completa — ML Pipeline · App Flutter · Backend · Monitoring

Problema: Vitalia sufre ~35% de fraude en autoregistro de actividad física. Esta solución infiere automáticamente la actividad desde el acelerómetro + giroscopio del smartphone on-device (sin stream a la nube), clasifica 6 actividades, detecta caídas para el segmento 65+, y actualiza los VitaPoints automáticamente en un backend self-hosted en EEE (RGPD by design).

Notebooks

01_eda_activities.ipynb
EDA actividades
Análisis exploratorio UCI HAR + MotionSense + PAMAP2. Distribución de clases, análisis SVM, efectos del augmentation, comparativa placement bolsillo vs cintura.
02_eda_falls.ipynb
EDA caídas — SisFall 4505 grabaciones
Distribución pico SVM por tipo de caída, análisis inmovilidad post-caída, diferencia señal jóvenes vs ancianos. Motivación umbral 3g para Stage 1 cascada.
03_fall_baseline.ipynb
Baseline LR + RF LOSO
Features manuales (peak SVM, energía, duración, varianza post-caída). LR: Recall 0.885, AUC 0.959. RF: Recall 0.931, AUC 0.986. Motiva arquitectura CNN.
03_har_training.ipynb
1D-CNN HAR — 54 sujetos LOSO
CNN 1D: Conv1D(64)→BN→Pool→Conv1D(128)→BN→Pool→Conv1D(128)→BN→GAP→Dense(64)→Softmax(6). F1-macro LOSO 0.87. Ablación CNN+GRU. Exporta har_model_keras.keras.
04_fall_detection.ipynb
CNN binario — Recall 1.0, F1 0.98
SMOTE + class_weight. Curva PR con 3 puntos de operación (conservador 65+, equilibrado, estricto). Cascada 3 etapas. TFLite INT8: 22 KB, 0.02ms p99. Exporta fall_model_int8.tflite.
05_tflite_benchmark.ipynb
Compresión + OTA promotion
FP32 341KB → FP16 179KB → INT8 105KB. Accuracy delta: −1.0%. Latencia 0.09ms. Batería: 0.009mW media (duty-cycle 0.004%). Sección de promoción: sube .tflite + model_meta.json a MinIO.

Preprocesado compartido — src/preprocessing/windowing.py

resample()
Resamplea señal a 50 Hz. Normaliza datasets que vienen a 87, 100 o 200 Hz.
sliding_window()
Ventanas de 128 muestras (2.56s) con 50% solapamiento para actividades.
compute_svm()
Signal Vector Magnitude √(ax²+ay²+az²). Invariante a rotación del dispositivo.
detect_impact_peaks()
Localiza el pico de impacto en la señal SVM (umbral configurable). Usado para centrar la ventana de caída.
extract_fall_window()
Extrae ventana de 100 muestras centrada en el pico de impacto (pre=50, post=50).
augment_window()
Augmentation: rotación de ejes, permutación, ruido gaussiano, time-warping. Invarianza de colocación.

Flujo de datos on-device

Sensor → Inferencia → UI → Backend (cada frame @50Hz)
SensorService.sampleStream
  │
  ├─► SlidingWindowBuffer(128, overlap=0.5)
  │         │ cuando buffer lleno (cada ~1.28s)
  │         └─► HarClassifier.classify(window) → HarResult{activity, confidence, pts/min}
  │                   │
  │             setState() → UI actualiza actividad + icono
  │             Timer(1min) → PostActivity(activity, 60s) → backend acumula VitaPoints
  │
  └─► SlidingWindowBuffer(100, overlap=0.5)
            │ cuando buffer lleno (cada ~1s)
            └─► FallDetector.analyze(window)
                      │
                      Stage 1: SVM peak > 3.0g ?
                        NO → FallResult(stage=0)
                        SÍ → Stage 2: CNN prob > threshold ?
                               NO → FallResult(stage=1)
                               SÍ → Stage 3: last 25 samples std < 0.1 ?
                                      → FallResult(stage=2 o 3, isFall=true)
                                            │
                                      DB.insertFallEvent()
                                      ApiService.postFall() → backend
                                      showDialog("¿Estás bien?")

OTA de modelos al arrancar

ModelUpdateService.checkAndUpdate() — ejecutado en _init()
GET /models/latest → {name, version, size_kb, filename}
  │

  │       SÍ → usar paths guardados en SharedPrefs (si existen en disco)
  │       NO → GET /models/{filename} → stream → File(documentsDir/{filename})
  │                 SharedPrefs["ota_model_version"] = nueva_versión

Art. 17 — Derecho al olvido
DELETE /users/{id}/data → borra usuario + cascade en PostgreSQL (activity_events, fall_events, vitapoints_ledger, consents) + purga MinIO training-data/{hash}/. Accesible desde Settings en la app.
DPIA obligatoria
Art. 35: tratamiento a escala de datos de salud + perfilado con efectos en póliza. Mitigaciones: on-device inference, pseudonimización, TTL, TLS 1.3, LUKS en disco servidor.
Sin transferencias internacionales
Backend en Hetzner Frankfurt (Alemania, EEE). Sin SCC, sin BCR, sin riesgo Schrems II. Ventaja competitiva frente a soluciones cloud AWS/GCP.
