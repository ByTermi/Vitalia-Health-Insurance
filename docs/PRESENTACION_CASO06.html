Preprocesado · V1
Ventaneo + Augmentation = Robustez de Colocación
Resuelve R2: el teléfono puede ir en el bolsillo, mano, brazalete o bolso — el modelo funciona igual
📏 Ventana deslizante — HAR
Input: Accel (ax,ay,az) + Gyro (gx,gy,gz) @50 Hz │ ├─ Filtro Butterworth paso-bajo 20 Hz ├─ Normalización por sujeto (μ=0, σ=1) │ Ventana: 128 muestras × 6 canales = 2.56 s · solapamiento 50% → tensor [N, 128, 6]
128 muestras = benchmark UCI HAR · capta ≥2 ciclos de paso · CNN-friendly
⚡ Ventana de impacto — Caídas
Pico SVM > 3g detectado │ Ventana: 100 muestras (2 s) centrada en el pico de impacto → tensor [100, 6] Maximiza información del momento exacto
🔄 Data Augmentation — Robustez colocación (R2)
Rotación/permutación ejesbolsillo/mano/brazalete
Ruido gaussiano σ=0.01gvariabilidad entre sensores

📐 SVM — Signal Vector Magnitude
SVM = √(ax² + ay² + az²) Invariante a la orientación del teléfono. Stage 1 fall detector: siempre activo (<1mW). Gate estático: SVM < 0.05g → stationary (evita que mesa vibración → "upstairs")

🔧 Técnicas de compresión (V4)
  • GlobalAveragePooling1D en vez de Flatten — menos parámetros
  • Post-training quantization INT8 — pesos y activaciones a entero
  • Duty-cycling — inferir 1 vez cada 1.28 s, no continuamente

  • Fall model solo 9.300 params — arquitectura mínima suficiente

Trade-off · R4 · V3
FN vs FP — No hay un umbral universal
La decisión del umbral es de negocio, no solo técnica. Vitalia lo configura por perfil actuarial.
💀 Falso Negativo (FN)
El sistema NO detecta una caída real
→ Anciano sin asistencia → riesgo vital
→ Responsabilidad potencial de Vitalia
🔔 Falso Positivo (FP)
Sistema detecta caída sin que haya ocurrido
→ Alarma innecesaria a familia
→ Desconfianza → desinstalación de la app
