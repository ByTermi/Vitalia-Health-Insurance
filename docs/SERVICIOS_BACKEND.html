Servicios del Backend

Referencia para la app Flutter — qué endpoints consume y de qué contenedores depende

§1 Endpoints HTTP

MétodoRutaFunciónApp Flutter
GET /health Estado de api, db, redis, minio usado icono cloud AppBar + test tab
POST /events/activity Registra actividad, calcula VitaPoints, devuelve total + nivel usado timer cada 60 s en home_page
POST /events/fall Registra caída, encola en Redis para alerta 30 s usado cascada stage ≥ 2
POST /events/fall/{id}/ack Cancela alerta — usuario respondió "Estoy bien" usado dialog caída
GET /users/{id}/vitapoints Devuelve total, semana, racha y nivel usado al arrancar la app
GET /models/latest Metadatos del modelo TFLite más reciente en MinIO usado OTA al arrancar
GET /models/{filename} Descarga el .tflite desde MinIO (streaming) usado si versión nueva en OTA
DELETE /users/{id}/data Derecho al olvido Art. 17 RGPD — borra usuario en cascada usado Settings → "Borrar mis datos"
GET /metrics Métricas Prometheus (latencia, contadores) solo infra Prometheus scraping

§2 Contenedores Docker

api (FastAPI)
Puerto 8000
API REST principal. Recibe todas las peticiones HTTP de la app. Expone /health y /metrics además de los routers.
db (PostgreSQL 16)
Puerto 5432 (interno)
Persistencia de usuarios, activity_events, fall_events, vitapoints_ledger y consents. TTL enforced por el worker.
redis
Puerto 6379 (interno)
Cola vitalia:falls — buffer entre la API y el worker para el pipeline de alertas de caída.
worker
Sin puerto expuesto
Consume la cola Redis. Espera 30 s ACK. Si no hay respuesta → ntfy + SMTP. Cron RGPD los domingos 03:00.
minio
Puertos 9000 / 9001
Almacén S3-compatible. Buckets: models/ (TFLite OTA), training-data/ (opt-in), mlflow-artifacts/.
ntfy
Puerto 8080 (interno)
Push notifications self-hosted. El worker publica aquí la alerta de caída si el usuario no responde.
mlflow
Puerto 5000
Model registry + experiment tracking. Gestiona qué versión de modelo TFLite sube a MinIO para OTA.
prometheus
Puerto 9090
Scraping de /metrics cada 15 s. Almacena series temporales de latencia por endpoint y contadores de eventos.
grafana
Puerto 3000
Dashboard de monitorización conectado a Prometheus. Visualiza latencia, FPR en producción, VitaPoints acumulados.

§3 Flujos end-to-end

3.1 · Actividad detectada → VitaPoints
App (timer cada 60 s, si actividad activa)
  │
  ├─ POST /events/activity {user_id_hash, activity, duration_s}
  │         │
  │         ├─ api  → calcula points = duration_s/60 × POINTS_PER_MINUTE[activity]
  │         ├─ db   → INSERT activity_event + vitapoints_ledger
  │         └─ →    {vitapoints_earned, total_vitapoints, streak_days, level}
  │
  └─ App actualiza _vitaPoints, _streakDays, _level
3.2 · Caída detectada → alerta
App (sensor stream)
  │
  ├─ Stage 1: SVM > 3 g  →  Stage 2: CNN prob > threshold
  │
  ├─ POST /events/fall {user_id_hash, stage, svm_peak}
  │         ├─ api   → INSERT fall_event (status="pending")
  │         ├─ redis → LPUSH vitalia:falls fall_id
  │         └─ →    {fall_id, status="pending", ack_deadline_s=30}
  │
  ├─ App muestra dialog "¿Estás bien?" (30 s)
  │
  ├─ Si ACK: POST /events/fall/{id}/ack → status="acked" → worker no alerta
  │
  └─ Sin ACK: worker espera 30 s → ntfy + SMTP → status="alerted"
3.3 · OTA de modelos al arrancar
App (inicio)
  │
  ├─ GET /models/latest → {name, version, size_kb, filename}
  │
  ├─ Si version != SharedPrefs["ota_model_version"]:
  │     GET /models/{filename} → stream → File(documentsDir/filename)
  │     SharedPrefs["ota_model_version"] = version
  │
  └─ Interpreter.fromFile(path)  [fallback: fromAsset si falla]
3.4 · Derecho al olvido (RGPD Art. 17)
App (Settings → "Borrar mis datos del servidor")
  │
  ├─ DELETE /users/{user_id_hash}/data
  │         ├─ api  → db.delete(user) CASCADE
  │         │         → borra: users, activity_events, fall_events,
  │         │                  vitapoints_ledger, consents
  │         ├─ minio → remove training-data/{user_id_hash}/*
  │         └─ → 204 No Content
  │
  └─ App: _vitaPoints=0, _streakDays=0, _level="bronze"
